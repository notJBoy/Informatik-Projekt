# 29.04.2026

## User-Prompt
"wenn man seinen benutzernamen ändern möchte, dann erhält man nach dem drücken auf \"speichern\" den error \"❌ Server nicht erreichbar\". Man sieht auch, dass keine Anfrage im backend ankommt. Schau dir an, warum das so ist und fixe anschließend, damit man den Account-Benutzernamen funktionsfähig ändern kann."

## Analyse
- Die Funktion `changeUsername()` in `current_dashboard.php` hat den Request direkt an das Python-Backend gesendet: `PUT ${BACKEND_URL}/auth/change-username/${CURRENT_USER_ID}`.
- Andere Account-Flows (z. B. E-Mail-Änderung) verwenden stattdessen einen lokalen PHP-Proxy unter `auth/*.php`.
- Dadurch war der Browser-Aufruf fehleranfällig ("Server nicht erreichbar") und es kam kein robuster, konsistenter Request-Flow über die bestehende PHP-Bridge zustande.

## Umgesetzte Änderungen
1. Frontend-Request angepasst in `current_dashboard.php`
- `changeUsername()` ruft jetzt `auth/change_username.php` via `POST` auf.
- Fehlerausgabe wurde auf `data.detail || data.error || I18N.errorGeneric` erweitert.

2. Neuer PHP-Proxy-Endpunkt erstellt: `auth/change_username.php`
- Prüft Request-Methode (`POST`).
- Prüft Session/Auth über `require_auth()`.
- Validiert `new_username`.
- Leitet intern an das Backend weiter: `backend_request('PUT', "/auth/change-username/$user_id", $payload)`.

Validierung:
